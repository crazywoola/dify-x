一句话心智模型

Workflow 管秩序，Agent 管判断，Skill 管方法，Stripe 管事实。

Workflow = SOP

输入、分支、确认与输出是确定的。

Agent = 同事

面对开放任务，判断何时用什么能力。

Skill = 作业指导书

把 Stripe 操作步骤、脚本和边界封装起来。

Stripe = System of Record

客户、价格、订阅和 Payment Link 的真实状态。

2:10–3:00。这是全场最重要的一页。强调 Agent 不是 Workflow 的替代品；高风险系统里，两者是互补关系。

Demo A · Build Agent

第一段自然语言：先“招聘”一个 Stripe Billing Operator。

● ● ●AGENTS → CREATE → BUILD MODE
构建一个 Stripe Billing Operator： 1. 仅允许 Stripe Sandbox；密钥来自 Secret 环境变量 STRIPE_SECRET_KEY。 2. 创建 stripe-billing Skill；支持按 email 查询客户/订阅，和创建 Payment Link。 3. 默认只读；写操作先返回 proposed_action，仅当任务包含 APPROVED=true 才执行。 4. 禁止退款、取消订阅、删除对象；禁止接收或输出卡号。 5. 输出严格 JSON：status, action, customer_id, payment_link, object_ids, evidence, error。 6. 使用 Stripe Python SDK，并生成一份可读的 build note。

Dify 1.16.x Build mode 可以通过对话配置 Prompt、Skills、Files 与环境变量；环境变量可标记为 Secret。详见 Build an Agent。

3:50–5:50。现场粘贴这段 Prompt。等待 Builder 时解释：不是让模型“记住规范”，而是要求它把规范写进 Agent 配置、Skill 和 build note。若网络慢，直接跳到下一页展示预期 Build draft。

● ● ●⌘K → /create
创建一个 Workflow：Stripe Payment Link Copilot。 输入：customer_email、plan_name、unit_amount、currency、request_id。 先校验 email 非空、unit_amount > 0、currency ∈ usd/eur/gbp；生成 proposed_action 摘要。 通过 Human Input 节点让操作员确认；仅确认后调用已发布的 Stripe Billing Operator Agent，任务中加入 APPROVED=true。 要求 Agent 返回 JSON；成功输出 payment_link 与 object_ids，失败进入可读错误分支。 不要创建退款、取消或删除路径。

/refine · 用反馈迭代 DSL

第三段自然语言：不是重画，而是补上生产语义。

● ● ●⌘K → /refine
Refine this workflow: 1. Reject 分支必须直接结束，不能调用 Agent。 2. 给 Agent task 增加 request_id 和 APPROVED=true。 3. Agent 输出必须包含 status 与 evidence；解析失败进入错误分支。 4. 最终输出不得包含任何 Secret 或完整卡号。 5. 保留现有输入字段，不改变 unit_amount 的整数单位。

何时用，何时不用

Agent 擅长判断，不该替你定义财务政策。

适合 Agent

  • 跨对象查询与归纳
  • 根据上下文选择只读工具
  • 生成拟执行动作与解释
  • 把非结构化工单转成结构化任务

留给确定性节点 / 人

  • 金额计算与币种校验
  • 折扣、退款、取消政策
  • 高金额与不可逆动作授权
  • 合规判断与异常兜底
17:25–18:10。回答“为什么不用一个 Agent 全包”。越靠近资金与政策，越需要确定性逻辑和明确责任人。
